# 🎬 Series Tracker

Telegram-бот для автоматического оповещения о выходе новых серий любимых сериалов.

## 📌 Описание

Пользователь подписывается на сериал → бот периодически проверяет расписание выхода через внешние API → при появлении новой серии отправляет уведомление в Telegram.

## 🛠 Технологический стек

| Компонент | Технологии |
|---|---|
| Язык | Java 17 |
| Фреймворк | Spring Boot |
| ORM | Hibernate |
| База данных | PostgreSQL |
| Миграции | Liquibase |
| Тестирование | JUnit, Mockito |
| Сборка | Gradle |
| Логирование | SLF4J + Logback |
| Внешние API | TMDB API, Kinopoisk API, MovieLab API |

## 🏗 Архитектура

Приложение построено по многослойной архитектуре:

Telegram Bot (входящие команды)
      ↓
Facade Service (единая точка входа)
      ↓
Service Layer (бизнес-логика)
      ↓
Repository Layer (доступ к БД)
      ↓
PostgreSQL

### Использованные паттерны проектирования

| Паттерн | Применение |
|---|---|
| **Adapter** | Унификация работы с тремя внешними API (TMDB, Kinopoisk, MovieLab) |
| **Strategy** | Единый интерфейс для работы с внешними API (TMDB, Kinopoisk, MovieLab). Каждый источник данных реализует общий контракт, что позволяет легко подключать новые API и переключаться между ними |
| **Facade** | Координация нескольких сервисов (подписки, поиск, уведомления) через единую точку входа для Telegram-бота. Бот вызывает только методы фасада, ничего не зная о внутренней структуре приложения |
| **Template Method** | Единый алгоритм обработки команд пользователя: валидация → выполнение → отправка ответа. Каждая конкретная команда (`/subscribe`, `/unsubscribe`, `/list`) реализует только свою специфичную логику, оставаясь в рамках общего шаблона |
| **Factory** | Создание UI-компонентов (кнопки, клавиатуры, сообщения) для Telegram-бота. Инкапсулирует логику построения интерфейса, избавляя сервисный слой от работы с Telegram-специфичными объектами |
| **Repository** | Абстракция доступа к данным |
| **Dependency Injection** | Управление зависимостями (Spring) |

## 🚀 CI/CD (GitHub Actions)

Настроен автоматический деплой на VPS через GitHub Actions и Docker:

### Процесс деплоя:

| Шаг | Действие |
|---|---|
| 1 | GitHub Actions (облако) компилирует проект и собирает JAR |
| 2 | JAR упаковывается в Docker-образ с помощью Dockerfile |
| 3 | Образ загружается в Docker Hub |
| 4 | VPS скачивает новый образ из Docker Hub |
| 5 | Docker Compose перезапускает контейнеры с обновлённым образом |
